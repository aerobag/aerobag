What is it?

Aerobag is a flight planning tool and electronic flight bag. It works the same online as a web app (for flight planning on the big screen) and as an Android app (for taking charts and plates with you offline).

Where did it come from?

I have been using Avare for almost as many years as it has existed. I love that it's open source. I love that I can have as many copies on as many devices as I want, so I have backups for my backups. (In fact, it was Garmin's device limit policy that drove me to cancel my Pilot subscription.) I love that it runs on Android so I don't have to use Apple's walled garden to take charts in the plane.

As awesome as all that is, I thought maybe it was time to take a stab at refreshing the concept. Aerobag a very direct descendent of Avare: you'll see its heritage everywhere. Here are some things that improve:

  • Same app web and tablet. The web (online) app fetches data on demand; don't try to use it on a poor hotspot. The tablet (offline) app lets you prefetch packages for the areas and types of flying you do.
  • Android Aerobag can manage multiple cycle packages simultaneously, so you can fetch the next cycle when the FAA publishes it (~20 days ahead) and already have it with you on your flight.
  • Offline regions depicted on map to help you plan packages
  • Efficient live weather feed protocol (if your hotspot works in the cockpit)
  • Rich vector layer with airports and airspaces
  • Click to inspect features on the map
  • Airways, approaches, STARs and SIDs
  • Terrain warning layer
  • Better-organized plates and CSup pages
  • TACs paint over Sectionals so you don't have to switch between them
  • Warnings about stale data
  • Aircraft profiles and altitude/wind planning.

Missing features

  • No supported ADS-B traffic or live remote-aircraft ownship modes
  • No 3D mode

Future ambitions

  • Capture and save flight logs
  • Better airway selection and flight plan manipulation

Privacy

Aerobag doesn't have a privacy policy; you should assume we've been taken over by private equity and have already sold your middle initial.

That said, when you visit aerobag.org on the web, data is fetched on demand, which means the server traffic reveals what part of the world you're looking at. The Android client preloads packages, which reveals much coarser information, but its live-feed data stream may similarly reveal location information. aerobag.org also learns your IP addresses.

Aerobag writes your preferences to the device you're using (Android or browser localStorage). Preferences include things like your flight plan, knobs on the Settings page, which Offline Packages you want to fetch and store.

Aerobag Cloud

If you use multiple devices, you can synchronize your preferences among them by linking each device to the same Aerobag Cloud Sync Account. Each Sync Account has an Device Setup Code with an *encryption key* that only the devices know, and some cloud *provider* that stores the data (but cannot read it). If you use the default aerobag.org Cloud provider, it sees your usage patterns and IP addresses, but never has access to your unencrypted data. It is important to understand that, if you do not save the Device Setup Code, you will not be able to recover your account data, even if it's stored in your own server or Google Drive.

Self-host for ultimate privacy

If you want to guard your privacy more closely, note that all of aerobag is open source. You can run your own server instance, which will fetch data from government sources. You can run your own Cloud instance, which will store your Cloud data locally.

Permissions

  • Location is used to plot your position on the map.
  • Notification permission is used to keep the GPS active and to keep background downloads running when you change apps or the tablet display sleeps.
  • Camera permission is used to scan a QR code when you link devices' Cloud sync accounts.
