# Responsible Coding Patterns

Keep domain logic out of platform UI. Web, Android, and any other platform layer should render decisions already made by core, plus perform platform-specific adaptation such as fetching bytes, caching assets, handling gestures, and painting native primitives. If behavior needs to match across platforms, put the shared decision in core or in preprocessing data products, then expose the narrowest UI-facing shape needed to draw it. Duplicating classification, sorting, eligibility, or styling policy in platform UI creates parity drift and makes later fixes expensive.

Do not add fallback paths that hide current data-product defects just because a regenerated snapshot is expected soon. A fallback that makes missing or malformed preprocessed data look valid turns a detectable build/product bug into silent behavior, and the temporary code tends to survive past the moment it was meant to bridge. Fix the producer, fail visibly when the required contract is absent, and only add compatibility handling when we intentionally support multiple durable data contract versions. If compatibility is necessary, label it as versioned compatibility, test it, and define when it can be removed.
